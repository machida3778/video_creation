# データで見るランキング: 台本の書き方

比較条件をそろえた **1つの指標** で順位を決め、数字と理由で違いを説明する。`docs/SHORTS_CRAFT.md` に従い、順位の読み上げだけで終わらせない。根拠は `research.json` の `sources` と `facts` にまとめる。

## フックと比較条件

- フックを **4案以上、3種類以上の型**（問い／意外な主張／数字／誤解の指摘など）で考え、採用案を1行目に、候補を `script.json` の `hook_options` に残す。
- **フックで順位の基準を1つと件数を明示**する。例:「人口密度で比べた上位5地域は？」。年次・対象地域・母集団・単位も冒頭の短い行でそろえる。「住みやすさ」など別の評価基準に途中で切り替えない。
- 0秒から話し始める。挨拶・自己紹介・「今回は〜」を入れない。主要な検索語を `search_query` に1つ書き、画面にも自然に使う。

## 順位の構成

- `route.params.items` の数（未指定は **5件**）を約束し、**第N位から第1位へ** カウントダウンする。登場項目は約束した数ちょうど。重複・欠番・同順位を入れない。
- **各順位に「項目名＋出典つきの値（単位つき）」と「理由の1行」** を必ず付ける。事実・数値・理由を述べる行の `fact_ids` は `research.json` の事実に対応させ、その事実の `source_ids` から一次資料までたどれるようにする。
- 同じ年次・集計方法の数値を使う。表示の丸めで同値になっても、順位は確認できる原数値に基づく。同順位しか作れないデータは採用せず、別のデータを選ぶ。欠測を推測で埋めたり、恣意的な第2基準で順位を決めたりしない。
- **第1位の直前に引き直しを1回** 入れる。最後の項目への新しい疑問や根拠を出し、すぐ第1位で回収する。50秒以上なら30〜40秒にも意味のある引き直しを置く（同じ位置なら兼用可）。
- 最後は第1位の値・理由と、持ち帰れる発見で締める。新たなランク外項目を追加しない。冒頭の問いを回収し、CTAは最大1つ、余韻で尺を水増ししない。

## 自信をもって言い切る（2026-11-10 ユーザー指示）

ランキングはエンターテインメント。保険をかけると面白さが落ちる。

- 「独断」「偏見」「勝手に」「根拠はない」「個人的には」「主観」「異論は認める」「諸説あり」「あくまで目安」「登録者数は人気の物差しのひとつ」のような断り・言い訳・締めの注意書きを、タイトル・台詞・カード・表紙・説明文のどこにも書かない。QA の `confidence` が止める。
- 指標と出典は冒頭の比較条件と `source_card` で一度示せば十分。正確さは出典で担保し、言い方は断定する（「第1位は〇〇。2位に1.5倍の差」）。
- 最後は第1位の圧倒的な強さや意外な発見で、余韻を残して終える。

## 行の書き方

- `script.json` は `vg/schemas.py` の `Script` に合わせる。話者は `narrator`、`cast` は解決済みの音声ID。順位用の独自フィールドは作らず、順位・項目・値は行の `text` に書く。
- 1行1文、全角15〜24字を目安、長くても40字以内。数値と理由が長ければ行を分ける。声は約8字/秒、VOICEVOXはspeedScale 1.3前後、行間を詰める。
- 数字・単位・固有名詞・略語の読みが曖昧なら、行全体の読みを `yomi` に書く。`emphasis` は各行1語まで。出典のない数字、因果関係の誇張、つなぎだけの行は使わない。
