# サムネイル（表紙）の作り方

記事・研究・プラットフォームのヘルプ・クリエイターの話（2024〜2026年）から、ハーネスで守らせるルールをまとめる。数値の多くは検証用の暫定値（**暫定**）で、公式の仕様は「仕様」と書く。人が選んだ表紙を優先し、毎日の自動投稿では Claude が下の採点で選ぶ。

## 惹きつける見出し（最優先）

表紙の役目は「この続きを知りたい」と思わせること。読みやすさの規則（後述）は、それを満たした案に対して守る。2026-11-05、答えを先に言う見出し（主語もない）が「人を魅了できない」と指摘されたため追加した。

- **具体さは「ちょうどよく」**: 何の話か（主語）は具体的に書き、答え（理由・仕組み・結論）は書かない。見出しの具体さとクリック率は逆U字の関係で、あいまいすぎても具体的すぎても下がる（Upworthy の 8,977 件の A/B テストの分析: [Le Quéré & Matias 2025, Scientific Reports](https://pmc.ncbi.nlm.nih.gov/articles/PMC11704130/)）。
- **一部だけ見せて核心は伏せる**: 驚く事実の一部を見せ、核心は動画で明かす。全部を隠すより強い（[Birdy](https://birdy-official.co.jp/youtube-samune-19tips/)、実務の経験則）。
- **意外性を入れる**: 常識の逆・矛盾・意外な数字・ありえない組み合わせ。好奇心は「知っていること」と「知りたいこと」の隙間で生まれる（情報ギャップ理論、Loewenstein 1994。上の論文の背景）。
- **タイトルと役割を分ける**: タイトルは検索される主語と文脈、表紙は感情を動かす一言。同じ文言を繰り返さない（[Birdy](https://birdy-official.co.jp/youtube-samune-19tips/)、[1of10](https://1of10.com/blog/how-to-make-thumbnails-like-mrbeast/)）。
- **画像が主張を見せる**: 見出しの「おかしな点」（へこみ・数字の対象・比べる2つ）が画像で一目で分かること。主張と違う部分が写った画像は使わない。
- **動画で必ず回収する**: 表紙の約束には動画で答える。答えのない釣りは視聴維持を下げ、方針にも反する（[YouTube](https://support.google.com/youtube/answer/9229980)）。

型（3案はなるべく別の型にする。問いだけの案は1つまで）:

| 型 | 形 | 例 |
|---|---|---|
| 常識の逆 | 「〇〇は実は△△」「〇〇なのに△△」 | 「虹は本当は丸い」 |
| 意外な数字 | 主語＋驚く数字 | 「〇〇は たった0.1ミリ」 |
| わざと・正体 | 「〇〇は わざと」「〇〇の正体」 | 「その形は わざと」（主語を必ず添える） |
| ありえない組み合わせ | 「〇〇の中に△△」 | 「〇〇に 小さな△△」 |
| 具体的な問い | 「なぜ〇〇は△△？」（問い自体が意外なときだけ） | 「なぜ虹は 曲がってる？」 |

使わない見出し: 答え・仕組みを言い切る（「〜で強くなる」「〜のおかげ」「〜だった」）、主語がない、抽象語だけ（「すごい理由」「衝撃の事実」）、タイトルと同じ文言、動画にない約束や誇張。

## 表紙専用の画像（2026-11-06）

動画のシーン画像は、ナレーションの1行を説明するために作られている。止め絵の表紙にすると「後ろ姿が扉から出ていく」のような雰囲気だけの画になり、主張も驚きも見えない（「就活で未来は狭まる？」の表紙が「動画の一シーンで魅了されない」と指摘された）。そこで表紙の画像は表紙のために作る。

- **3案のうち2案以上は表紙専用の画像**にする。`covers.json` の案に `image` の代わりに `prompt`（必要なら `negative`・`seed`）を書くと、`vg assets` がシーンと同じGPUジョブで `cover_<id>` を生成する。シーン画像を使うのは、その画像が下の条件をすでに満たすときだけ。
- プロンプトは英語で、次の順に書く:
  1. **見出しの「おかしな点」そのものを主役にする**: 数字の対象・比べる2つ・欠けたもの・壊れたもの。主役は1つで、画面の横幅の40〜65%を占める寄りの構図。例: 「大卒の3人に1人 3年で…」なら、並んだ3つの同じ椅子のうち1つだけが空いて倒れている。後ろ姿の人物ではない。
  2. **画像だけで「何が起きている？」と思わせる**: 1つだけ違う・前後の対比・大きさの対比・ありえない組み合わせ。説明を聞かないと意味の分からない比喩（道・扉・分かれ道・天秤・歩き去る人影・風景）は、それ自体が主張でない限り使わない。
  3. **見出しの置き場所を空ける**: 主役は中央の領域に置き、見出しの位置（上か下の3分の1）は暗く平らな余白にする（例: `plain dark empty space in the lower third`）。
  4. **光と色**: 光源は1つで強く、主役と背景のコントラストをはっきりさせる。色は抑え、`palette` と合うアクセントを1色だけにする（チャンネルの見た目は上品・クール。かわいいキャラクターや多色の装飾は使わない）。
  5. **入れないもの**: 画像の中の文字・数字（生成で崩れる）、実在の人物、写実的な人の顔。人物を出すなら顔の見えない様式化した姿。
- 生成した表紙は横幅180 pxの見本で、文字を隠しても主役と「おかしな点」が分かるかを確かめる。

## 採点と選び方

**採点**（各案を0〜2点、16点満点）: ①主語が一目で分かる ②答えを伏せている ③意外性・矛盾・数字がある ④画像が主張を見せる ⑤縮小しても読める（文字の規則） ⑥動画で回収される（`line_id`） ⑦表紙のための画（主役が大きい・見出しの余白がある・雰囲気だけのシーン流用でない） ⑧スクロール中に指が止まる（180 pxの見本を3秒見て、続きを知りたくなるか）。

- **採点は作った本人がしない**。見出しと画像を作ったセッションは自分の案に甘くなる（11/06の表紙は自己採点で12点満点だった）。採点は新しいサブエージェントに任せ、渡すのは各案の `thumbs/<id>_180.jpg` と `thumbs/<id>.jpg`、動画のタイトル、`line_id` の台詞だけにする（台本の意図や作者の説明は渡さない）。「Shorts の棚で上位の表紙と並べて、これを押すか」を厳しく判断させ、各項目の点と一言の理由を返させる。
- ②・④・⑥・⑦のどれかが0点の案は使わない。最高点が12点未満、または④か⑦が2点の案がないときは、見出しかプロンプト（またはシード）を作り直して `vg assets`・`vg thumbnail` をやり直し、もう一度採点させる（作り直しは1回まで。その後は最高点の案を使う）。
- 合計の高い順に `covers.json` に並べ、`covers_report.json` の `chosen_id` を最高点の案にする。採点の結果（採点者・各点・理由）は `covers_report.json` の `scores` と報告に書く。

## どこにどう表示されるか

- YouTube Shorts は表紙を縦長のまま見せるとは限らず、棚や検索では中央を切り取って表示されることがある（[YouTube ヘルプ](https://support.google.com/youtube/answer/72431)）。TikTok のプロフィール一覧は 3:4 程度に切り取られる（[測定例](https://www.socialtoolshed.com/tiktok/cover-size)）。
- そのため、**大事な文字と被写体は中央の領域**（1080×1920 のとき x 108〜864、y 480〜1440）に収め、9:16・3:4・4:5・1:1 で切り取った見本を作って確かめる（**暫定**）。
- 表紙は小さく表示される。横幅 120 px と 180 px に縮小した見本で、2秒以内に見出しが読めて被写体が分かることを人が確かめる（**暫定**）。

## 作るもの

- **案は3つ**（別の案が立たなければ2つ）。色違いではなく、上の型か構図を変える（[YouTube のテスト機能の考え方](https://support.google.com/youtube/answer/16391400)）。`template` の `reveal` は「意外な事実の提示」で、答えの提示ではない。
  - 順位のバッジ＋被写体（ランキングのみ。「第1位は？」は実際に順位と基準がある動画だけ）
- 1つの表紙で伝える主張は1つ。それを回収する台本の行を記録し、動画にない約束はしない（[誤解を招くサムネイルの方針](https://support.google.com/youtube/answer/9229980)）。

## 文字

- 日本語の見出しは **8〜12字**（数字・記号を含む）。最大でも20字。収まらなければ、文字を小さくする前に言葉を削る（[ytbs](https://ytbs.jp/book2026/5-1/)、[note: textstyle](https://note.com/textstyle/n/n03efc803c6ed)）。
- 見出しは3行まで、補助のバッジは1つまで。
- 太いゴシック体（ウェイト 700〜900）。横に潰した文字は使わない。
- 横幅 120 px に縮小しても、文字の高さが 14 px 以上（1080 幅の原寸で 126 px 以上、フレームの高さの約6.6%）。**暫定**
- 細かい画像の上の文字は、文字の高さの **6〜10%** の太さの縁取りを付けるか、背景の帯を敷く。
- 文字と縁取り・帯とのコントラスト比は **4.5:1 以上**（[WCAG](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) を採用）。

## 色と構図

- 見出し・バッジの色は **3色まで**（写真を除く）。白・黒・黄、白・黒・赤など。色だけで意味を区別しない（[Adobe](https://www.adobe.com/jp/express/discover/ideas/thumbnail/youtube)）。
- **主役の被写体は1つ**で、横幅の 40〜65%（**暫定**）。関係のない小物を並べない。
- 解説系は、驚いた顔より実物・仕組み・自前のキャラクターを主役にする。大げさな表情のサムネイルは多くない（[vidIQ の調査](https://vidiq.com/research/youtube-thumbnail-study/)、ツール会社の調査）。
- 矢印や丸囲みは **1つまで**。指す先は意味のある部分にし、ありもしない異常を示さない。
- シリーズでフォント・配色・バッジの位置を固定し、被写体と見出しの位置だけ変える。

## 書き出し

| 行き先 | 形式 |
|---|---|
| YouTube Shorts | 9:16、JPEG/PNG、2160×3840 を基本に（仕様: 高さ 640 px 以上、50 MB 未満） |
| TikTok | 1080×1920 の JPEG/PNG と、3:4（1080×1440）の切り取り見本 |
| X | 動画と同じ比率（1080×1920）、5 MB 未満 |

## AI生成の画像

- 表紙ごとに、AI生成か・写実的か・実在の人物や出来事を描くかを記録する。写実的な再現は人が確認する（[YouTube](https://support.google.com/youtube/answer/14328491)、[TikTok](https://support.tiktok.com/en/using-tiktok/creating-videos/ai-generated-content)）。

## 選び方と改善

- 候補・切り取り見本・文字数・コントラストの結果・回収する台本の行・採点を一緒に並べる。人が選んだらその案を `covers_report.json` の `chosen_id` に記録する。
- Shorts では YouTube の標準の A/B テストは使えない。表紙を変えたら、その記録を残して傾向として扱う。
